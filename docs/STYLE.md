# Style guide

This guide gives the writing rules of the project. Apply the rules to issues, pull requests, commit messages, documents and code comments.

The rules come from ASD-STE100 Simplified Technical English (STE100). STE100 removes words with more than one meaning and sentences with more than one structure. This decreases the risk that a reader, a translation tool or an AI agent misreads the text.

The official standard and its dictionary are free on request at [asd-ste100.org](https://www.asd-ste100.org/). ASD gives the right to copy the standard only to some organizations, and this project is not one of them. Thus this guide does not contain the dictionary.

## Rules

1. Use the active voice.
2. Write one instruction in each sentence.
3. Write a maximum of 20 words in an instruction, and a maximum of 25 words in a description.
4. Do not use semicolons. Write two sentences.
5. Do not use phrasal verbs, for example "set up", "clean up" or "pick up". Use one verb: "configure", "remove", "take".
6. Use simple tenses: the simple present, the simple past, the simple future and the imperative. Do not use compound tenses, for example the present perfect.
7. Use a maximum of three nouns in a noun cluster.
8. Use the same term for the same concept every time. The glossary gives the terms.
9. Use a list for three or more steps or conditions.
10. Write one topic in each paragraph. Write a maximum of six sentences in a paragraph.
11. Do not remove articles, subjects or verbs to make a sentence shorter.
12. Keep the level of certainty of a statement. If you are not sure, write "can" or "probably". Do not write a guess as a fact.

## Examples

| Do not write | Write |
|---|---|
| `The chunks are generated by the worker thread.` | The worker thread generates the chunks. |
| `Set up the CI and clean up the old files.` | Configure the CI. Remove the old files. |
| `The mesh has been updated.` | The app updated the mesh. |
| `The mesher is fast; it uses greedy meshing.` | The mesher is fast. It uses greedy meshing. |
| `the chunk mesh vertex buffer size` | the size of the vertex buffer of a chunk mesh |
| `Changes not saved will be lost.` | You lose the changes that you do not save. |
| `This change fixes the crash.` (a guess) | This change probably fixes the crash. |

## Glossary

Use these terms. Add a term when a new concept needs a name.

### Voxels and rendering

| Term | Definition |
|---|---|
| voxel | One cell of the world grid. A voxel has one block type. |
| block type | The material of a voxel, as a number (ID). |
| air | The block type of an empty voxel. Its ID is 0. |
| chunk | A box of voxels with a fixed size. The default size is 16 × 64 × 16. |
| region | A square group of chunks with the size of the start area (#19). |
| world | All the chunks of a game. |
| face | One of the six sides of a voxel. |
| visible face | A face of a solid voxel that touches air or the chunk border. |
| quad | A rectangle that the mesher makes from visible faces. A quad has two triangles. |
| greedy meshing | The method that joins adjacent visible faces with the same block type and direction into larger quads. |
| mesh | The quads of one chunk, ready for the GPU. |
| mesher | The code that makes a mesh from a chunk. |
| frame | One image that the app draws. |

### Project

| Term | Definition |
|---|---|
| core library | `ElysianOutpost.Core`. It does not use windows, input or the GPU. |
| app | `ElysianOutpost.App`. The executable that uses BRUTAL for the window, the input, the GPU and the debug UI. |
| legacy project | The Unity project in the folder `Elysian-Outpost/`. |
| port | To move code from the legacy project to the solution without a change of behavior, except the changes that the issue lists. |
| ADR | Architecture decision record. A document in `docs/adr/` that records one decision and its reasons. |
| asset | A media file of the game: an image, a 3D model, a texture, a color palette, a sound or a music file. Assets use the CC BY 4.0 license. |

### Simulation and pathfinding

| Term | Definition |
|---|---|
| tick | One fixed step of the simulation. |
| citizen | A settler that the simulation controls. |
| nav cell | A voxel position where a citizen can stand. |
| path | A list of nav cells from a start to a goal. |
| path cost | The sum of the step costs along a path. |
| approximation limit | The maximum ratio between the cost of a path and the cost of the shortest path. |
| shortcut | A new connection that makes a path much shorter, for example a bridge. |
| pheromone level | A number on a nav cell. It increases when citizens walk on the cell. It decreases with time. |
| deposit | To increase the pheromone level of a nav cell. |
| evaporation | The decrease of the pheromone levels with time. |
